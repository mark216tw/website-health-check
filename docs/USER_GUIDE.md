# 使用指南

本文件說明「網站健康檢查」的安裝、設定與日常操作。

## 1. 安裝與首次開啟

1. 下載 `app-prerelease.apk`。
2. 允許「安裝未知來源應用程式」後完成安裝。
3. 開啟 App。
4. Android 13 以上會詢問通知權限：
   - 允許：可接收網站異常與恢復通知。
   - 拒絕：仍可使用檢查與紀錄，但不會收到通知；可稍後到「設定 → 通知」開啟系統通知設定。

> `1.0.0-prerelease` 使用 Debug 金鑰簽署，僅供測試，請勿作為正式版本散布。

## 2. 新增網站

點擊網站清單右下角的「＋」按鈕。

### 基本資料

| 欄位 | 說明 |
|---|---|
| 網站名稱 | 顯示於清單、通知與紀錄，例如「公司官網」 |
| 網址 | 例如 `https://example.com`；未輸入 `http://` 或 `https://` 時會自動補上 `https://` |
| HTTP 方法 | `HEAD` 較省流量；`GET` 會下載內容。啟用內容檢查時會自動使用 `GET` |
| 逾時（秒） | 1–60 秒，預設 10 秒 |
| 狀態碼下限／上限 | 預期視為正常的 HTTP 狀態碼範圍，預設 200–399 |
| 跟隨轉址 | 遇到 3xx 時是否自動前往最終網址 |
| 失敗通知門檻 | 連續失敗幾次後發送通知，預設 3 次 |
| 啟用自動檢查 | 關閉後保留設定與歷史紀錄，但不執行檢查 |

### 內容字串檢查

啟用「檢查內容包含字串」後：

- 會自動改用 `GET` 下載頁面。
- 最多讀取前 **1 MB** 的原始回應內容。
- 比對**區分大小寫**。
- 狀態碼符合但內容不包含指定字串時，紀錄為 `KEYWORD` 失敗。
- 比對的是 HTTP 原始內容（HTML 原始碼），不是瀏覽器畫面文字。

### HTTP 明文警告

若網址使用 `http://`，欄位下方會顯示「使用 HTTP，內容未加密」。App 仍允許儲存與檢查，但建議優先使用 HTTPS。

### 重複網址

儲存時若偵測到其他網站使用相同（正規化後）網址，會顯示確認視窗：

- 「仍要儲存」：允許建立重複監控。
- 「取消」：回到表單修改。

## 3. 檢查排程

### 檢查星期

可勾選一至日。至少需選擇一天。

### 每日時間區段

設定每天允許檢查的開始與結束時間。

- 結束時間早於開始時間代表**跨越午夜**，例如 23:00–01:00。
- 開始與結束相同時，視為全天區段。

### 檢查頻率

以分鐘為單位，最低 **15 分鐘**，最高 1440 分鐘。

排程規則：

1. 儲存或重新啟用網站時，若目前時間落在檢查時段內，會**立即檢查一次**。
2. 之後的下次檢查時間為「上次檢查時間 + 檢查頻率」。
3. 若已超過預定時間，會在下一次排程機會立即補檢查。
4. 若下次時間落在時間區段外，會順延到下一個允許的時段。

範例：

- 檢查頻率 30 分鐘，11:47 完成檢查 → 下次約 12:17。
- 檢查時段 09:00–17:00，最後一次檢查 16:50 → 下次順延至隔天 09:00。

> Android 的 Doze／省電模式可能延遲背景工作。實際檢查時間可能晚於排定時間。

## 4. 網站清單

每張網站卡片顯示：

- 狀態：正常、異常、尚未檢查、已停用、檢查中
- 最近一次回應時間
- 連續失敗次數
- 上次與下次檢查時間
- 排程摘要

操作：

- 點擊卡片：編輯網站。
- 點擊重新整理圖示：立即檢查；檢查期間會顯示進度圈與「檢查中」。
- 切換開關：啟用／停用自動檢查。

### 排序

點擊右上角排序圖示，選擇排序方式後按「確認」：

1. 新增時間（舊→新）
2. 新增時間（新→舊）
3. 名稱（A→Z）
4. 名稱（Z→A）
5. 最近檢查（新→舊）
6. 最近檢查（舊→新）
7. 狀態（異常優先）
8. 回應時間（慢→快）
9. 回應時間（快→慢）

排序方式會保留，重新開啟 App 後仍生效。

## 5. 檢查紀錄

「紀錄」頁顯示最近 500 筆檢查結果（可依篩選條件匯出全部符合的紀錄）。

篩選：

- 全部／成功／失敗
- 特定網站

點擊紀錄可查看：

- 網站名稱、檢查時間、結果
- HTTP 狀態、回應時間
- 錯誤類型與完整錯誤訊息
- 原始網址、最終轉址網址
- 「複製」完整詳情

### 匯出 CSV

- 紀錄頁右上角下載圖示：匯出**目前篩選**的紀錄。
- 「設定 → 資料 → 匯出 CSV」：匯出**全部**紀錄。

CSV 欄位：

`網站名稱, 網址, 檢查時間, 結果, HTTP狀態, 回應時間(ms), 錯誤類型, 錯誤訊息, 最終網址`

檔案使用 UTF-8 with BOM，可直接以 Excel 開啟。

## 6. 通知

當網站連續失敗達到「失敗通知門檻」時，會發送一次異常通知；恢復正常時再發送一次恢復通知。

注意：

- 需要系統通知權限。
- 若通知頻道被關閉，App 不會收到通知；設定頁會顯示提示與系統設定入口。
- 同一段連續失敗期間不會重複發送異常通知。

## 7. 設定

### 顯示模式

- 系統：跟隨手機淺色／深色設定。
- 淺色。
- 深色。

系統列與導覽列圖示會同步切換。

### 通知

顯示網站異常與恢復通知開關，以及目前系統通知是否可用。

### 紀錄保留

可選 7、30、90、365 天。超過期限的紀錄會在：

- App 啟動時
- 每次變更保留天數時
- 每次檢查完成後

自動清除。

### 背景執行

顯示目前是否受電池最佳化限制，並提供「開啟電池最佳化設定」按鈕。若背景檢查經常延遲，可將本 App 設為「不受限制」。

Android 的 Doze 模式會把背景工作延後到維護窗口；未設定「不受限制」時，30 分鐘的間隔可能延遲超過 1 小時。建議同時檢查手機廠商的額外省電／自啟動限制。

### 排程診斷

顯示每個啟用網站：

- 下次檢查時間
- 上次檢查時間與距今多久
- 是否已逾期
- WorkManager 狀態（已排入、執行中、已完成等）

也會顯示看門狗狀態與上次執行時間。看門狗每 15 分鐘檢查逾期排程；逾期會在下次看門狗執行或開啟 App 時立即補檢查。

提供：

- 「重新整理」：重新查詢狀態。
- 「重新排程」：取消並重新建立所有啟用網站的排程。

### 資料

- 匯出全部 CSV。
- 清除所有檢查紀錄（網站設定會保留）。

## 8. 常見問題

### 為什麼等了一段時間還沒有自動檢查？

請確認：

1. 網站已啟用。
2. 目前時間在設定的星期與時間區段內。
3. 檢查頻率與上次檢查時間的間隔尚未到達。
4. 「設定 → 排程診斷」顯示的狀態是否為「已排入」。
5. 是否顯示「已逾期」；若是，看門狗或下次開啟 App 時會盡快補檢查。
6. 是否受電池最佳化或 OEM 省電機制限制。

### 立即檢查有紀錄，但背景檢查延遲

這是 Android Doze／省電機制造成的系統限制。可嘗試：

- 將 App 設為不受電池最佳化限制。
- 關閉手機廠商的額外省電限制。
- 保持網路連線。

App 內建看門狗會定期修復逾期或中斷的排程，但無法突破 Doze 的維護窗口限制。

### 通知沒有出現

- 確認系統通知權限已允許。
- 確認「網站狀態通知」頻道未被關閉。
- 確認失敗次數已達門檻。
- 確認「設定 → 通知」中的系統通知狀態正常。

### 內容檢查失敗，但瀏覽器看得到文字

內容檢查比對的是 HTML 原始碼，且只讀取前 1 MB、區分大小寫。若文字由 JavaScript 動態產生，可能不在伺服器回傳的原始內容中。
